## 1. Purpose

The eval umbrella turns component acceptance from opinion into evidenced judgment.
Every accepted component — skill, agent, or unit — passes prompt-invocation tests
and mission trials for its kind, in CI, with pinned-version scores. Any component
that does not pass through this umbrella stays a claim, however convincing it looks.

## 2. Per-kind trial packs (CI, pinned-version scores)

Three trial packs ship with the harness, one per component kind:

- `trial-pack-skills`: prompt-invocation tests plus mission trials for skills.
- `trial-pack-agents`: prompt-invocation tests plus mission trials for agents.
- `trial-pack-units`: prompt-invocation tests plus mission trials for units.

Each pack runs in CI. Each reported score is a pinned-version score: the score is
only valid bound to the exact pinned component version and the exact pack revision
that produced it. Re-running the same pinned version with the same pack on a clean
machine reproduces the same score; if the score changes, something unpinned changed.

Pinned-version record: `component <id> @ pinned version <semver>+<sha>; pack <pack-id> @ <pack-rev>; score <value>`.
Worked example: `component trial-pack-skills/smoke @ pinned version 0.9.5+6bf56ff; pack trial-pack-skills @ rev 1; score 0.91`.

## 3. Blind-spot-aware evaluator design

The evaluator is designed blind-spot-aware: evaluators never see generator rationales.
The generator's self-justification is withheld from the evaluator, so a fluent
rationale cannot launder a wrong result into a passing score. The evaluator grades
the artifact and the logs, never the story about the artifact.

## 4. Comparative-probe appendix (no-ground-truth work)

For work with no ground truth — plan quality, research quality — the comparative-probe
appendix is the authorized instrument, and there is no improvised alternative.
It compares proposal, sounding, and composition paths on defined behavioral axes
and reports the comparison; it never invents a private rubric per run.

## 5. HAL template (methodological gate)

Acceptance follows the HAL template with three non-negotiable clauses:

1. model-vs-structure split: a model improvement is never credited to the structure,
   and a structure improvement is never credited to the model.
2. mandatory log inspection: the score alone never tells how the component reached
   its result or what it hid; logs are inspected on every pass.
3. no scores-only pass: a component with a high score and suspicious or missing logs
   never passes, however tempting the score.

A score without a log is a story; a log without a score is a guess; together they are evidence.

## 6. Retro-sweep budget line (announced-coverage rule)

The release carries a written retro-sweep budget line: ~15-25 percent of effort on an
estimated-from-prior-study basis. Coverage is owed on every row accepted before
evaluation, and the sweep spends on rows actually accepted before evaluation — never
on comfortable new rows. Sweep coverage is announced, not implied.

Announced coverage: 17 of 23 pre-eval accepted rows swept (announced, not implied).

## 7. Long-context and fresh-window controls

- T7 long-context variants: every critical trial ships long-context variants, so a
  skill that works only in a fresh window is exposed here before it is exposed in a
  real owner session.
- T8 fresh-window rule: trials run under the fresh-window rule — no inherited
  context may carry the component across trials.

## 8. Exit criteria (proof, not opinion)

1. The component score is reproducible from its pinned version (section 2).
2. The retro-sweep coverage count is announced, not implied (section 6).
3. The deliberately-broken-component FAILs, and it must fail on log inspection even where a surface score would pass: the broken probe carries a real defect, not a cosmetic one — a defect that passes the surface score yet fails inspection. This proves inspection is genuinely mandatory. `scripts/verify-eval-harness.mjs` runs this probe on every invocation: the broken probe must FAIL and a clean control must PASS.
