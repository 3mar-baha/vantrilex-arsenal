# Priority Backfill — 2026-11-11 (W-19)

## Formula `w19-v1`

Per row, starting from a base of 5:

| signal | condition | contribution |
|---|---|---|
| `class` | `class === 'loadable'` OR (`class === 'installable'` AND `install_cmd != null`) | +1 |
| `when_to_use` | `when_to_use` is set | +2 |
| `version_pin` | `version_pin` is set | +1 |
| `install_cmd_null` | `class === 'installable'` AND `install_cmd == null` (installability claimed with no command — a contradiction) | −1 |

`class` never stacks: installable-with-command and loadable each yield one point,
not two. The total is clamped to 1–10.

Tier overrides, applied after the clamp and recorded in `usage_signals.overrides`:

- `tier === 'core'` → priority at least 8 (`core_min_8`). Fired **0 times** on
  this data: all 16 core rows carry `when_to_use`, so every core row's raw score
  is already ≥ 8 (9 with `version_pin` → 9; 7 loadable without pin → 8).
- The four top-level skills → priority 10 (`top_level_10`):
  `vantrilex-prime`, `vantrilex-vanguard`, `vantrilex-doctrine`,
  `vantrilex-workflow-forge`. Fired **4 times** (all four were raw 8).

## Unscored decision (the honest null)

A row whose four signals are all zero carries no discriminating information; a
flat 5 would be a non-score wearing a number. Such a row is emitted as
`priority: null`, `priority_source: "unscored"`, `priority_set_at: "2026-11-11"`,
and a `usage_signals` object whose `reason` field states the absence. Carve-outs:
`tier === 'core'` (registry curation — itself a signal) and the four top-level
ids are always scored.

**339 rows are unscored — every one is `class: "upstream"` with no `install_cmd`,
no `version_pin`, no `when_to_use`, and no contradiction.** All 1,117 installable
rows carry an `install_cmd` and a `version_pin`, so the `install_cmd_null` −1
branch is dead on current data (kept in the formula; if an installable row ever
loses its command the scorer will catch it).
