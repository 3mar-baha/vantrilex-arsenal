# 0.9.33 Depth-3 Apply-Time Spec

Status: draft-unlanded (bytes-inline; landing belongs to d33-spec-land).
Concern: depth-3 raise on apply, idempotent and verifiable, nothing beyond depth-3.
Artifact: `docs/0.9.33-depth3-spec.md`.
Lane: build (NO merge/tag/publish/release — park commit only).
`last_verified: unverified` — no verification run from this seat; github lander sets the date only on the verification that justifies it.

## 1. Purpose

This spec fixes the single apply-time mutation the 0.9.33-BUILD lane needs: raise `experimental.subagent_depth` to `3` where the running application actually loads it, without inventing scope.

## 2. Trigger

[N1] The mutation SHALL apply at apply time only, never at plan, verify, publish, or record time.

Apply time means the directed apply node inside the `wt/0.9.33-depth3` lane after W0 lands, immediately before any worker dispatch that needs depth 3. No other trigger satisfies this spec.

## 3. Semantics

[N2] If `experimental.subagent_depth` is missing or lower than `3` in the config the running application actually loads, the apply SHALL set it to `3`.

[N3] If `experimental.subagent_depth` is already higher than `3`, the apply SHALL leave it unchanged and SHALL NOT lower it.

[N4] The apply SHALL modify no other key, no other file section, and no other config value besides `experimental.subagent_depth` to `3` under [N2].

The only value this spec authorises is the integer `3`. No string form, no second key, no companion flag.

## 4. Idempotency

[N5] Re-applying this spec to the same loaded config SHALL produce zero additional diff: the first apply converges to `3`, every later apply is a no-op confirmed by read-back.

## 5. Fail-closed

[N6] On any doubt about which config file the running application loads, the current value, write permission, or restart requirement, the apply SHALL refuse the write, leave every file byte-identical, and state the exact reason.

A refused apply is a correct outcome, never a skipped check. A partial write is a violation.

## 6. Logging

[N7] Every apply attempt SHALL log the config path actually read, the value before, and the value after, in one auditable record before the node closes.

A log missing any of path, before, or after is incomplete.

## 7. Verification gates

All three gates MUST pass on the same apply; any failure is fail-closed per [N6].

- G1 read-back match: the value read back from the loaded config after apply MUST equal `3` (or the untouched higher value under [N3]), quoted with the path and the read command.
- G2 no-extra-diff: the apply diff MUST contain exactly the `experimental.subagent_depth` change and nothing else; any second key, whitespace-only file touch outside that key, or unrelated hunk FAILS G2.
- G3 no-lower: the apply MUST NOT lower any pre-existing value; a before-value higher than `3` MUST read back identical after apply.

## 8. Out of scope (refuse, never add)

- No merge, no tag, no publish, no release, no release asset.
- No `AGENT.md` write, no `WORKFLOW.md` write.
- No `arsenal.ts` write (read-only reference for this spec).
- No global-config write beyond the single loaded-config key authorised in [N2].
- No scripts/probe-path write.
- No value other than `3` under [N2], and no second key under [N4].

## 9. Language scope

EN-only per `AGENTS.md` Hard Rule 5. No Arabic mirror ships in this cycle; the exception is stated here, not assumed.

## 10. Beyond-depth-3 refusal

Any request to raise beyond `3`, to add a second depth key, or to widen this lane beyond the apply-time raise MUST be refused and escalated to the directing leader with the requested value and the reason it was refused. This seat never adds it.
