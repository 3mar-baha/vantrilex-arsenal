## 1. Purpose

This spec fixes the single apply-time mutation the 0.9.75 W0 lane needs: raise `experimental.subagent_depth` to `4` where the running application actually loads it, without inventing scope. The 0.9.33 cycle fixed the same mutation at floor `3`; this spec is its true successor and authorises only the integer `4`.

## 2. Trigger

[N1] The mutation SHALL apply at apply time only, never at plan, verify, publish, or record time.

Apply time means the `config:` hook on the plugin's `Hooks` object - registered by `setup()` on the OpenCode V2 `setup()` surface in `.opencode/plugin/arsenal.ts` - fires when the running application loads its configuration. It fires before the loaded configuration is used; no other lifecycle point satisfies this spec.

The authorised mutation lives in `.opencode/plugin/arsenal.ts`, `config:` member of the `Hooks` object returned by `server: Plugin = async (input: PluginInput): Promise<Hooks> => {`. ## 4. Idempotency

[N5] Re-applying this spec to the same loaded config SHALL produce zero additional diff: the first apply converges to `4`, every later apply is a no-op confirmed by read-back. Proof T4 exercises exactly this (two consecutive raises on the same object are byte-identical snapshots); proof T7 repeats the raise across three turns on independent objects with a deep-frozen template and identical outputs.

## 5. Fail-closed

[N6] On any doubt about which config file the running application loads, the current value, write permission, type/shape of the loaded value, or restart requirement, the apply SHALL refuse the write, leave every file byte-identical, and state the exact reason. Any unrecognised shape under `experimental` or `experimental.subagent_depth` returns without mutation (lines 3604, 3610). A refused apply is a correct outcome, never a skipped check. A partial write is a violation. The proof harness mirrors this: exit `2` on infra doubt (unreadable source, missing markers, unparseable hunk), exit `1` on any case failure, exit `0` only on all-pass.

## 6. Logging

[N7] Every directed apply node that performs a file write SHALL log the config path actually read, the value before, and the value after, in one auditable record before the node closes. A log missing any of path, before, or after is incomplete.

The plugin hook itself mutates the in-memory loaded config and performs no file write and no log emission; it is not the auditable record. For this cycle the auditable records are `.opencode/audit/ARSENAL-AUDIT-EXEC-001/dispatch-log.md` and the verbatim `node scripts/d4-depth-proof.mjs` output carried in the W0 reports. No other log is claimed.

## 7. Verification gates

All three gates MUST pass on the same apply; any failure is fail-closed per [N6].

- G1 read-back match: the value read back from the loaded config after apply MUST equal `4` (or the untouched higher value under [N3]), quoted with the path and the read command. Covered by proof T1-T4.
- G2 key/scope invariant: the apply diff MUST contain exactly the `experimental.subagent_depth` change and nothing else; any second key, whitespace-only touch outside that key, or unrelated hunk FAILS G2. Covered by proof T2 (exact key set) and T4 (snapshot equality).
- G3 never-lower: the apply MUST NOT lower any pre-existing value; a before-value higher than `4` MUST read back identical after apply. Covered by proof T5.
