# Three Facet Trials (MFT-113)

Owner ruling 2026-11-06: ONE seat, three facets (cautious / balanced /
long). SAME thinking, DIFFERENT required permissions per facet. Facet is
changed from the list/menu and the permissions change automatically via
`node scripts/switch-facet.mjs set <facet>`. Each trial below runs the
same concern (update `docs/03-ARCHITECTURE.md` matrix wording) under a
different facet and quotes the resulting differing behaviour.

## Trial 1 — cautious (asks often)

```console
$ node scripts/switch-facet.mjs set cautious
facet: cautious (permissions updated for cautious)
$ node scripts/switch-facet.mjs list
cautious (active)
balanced
long
```

Quoted behaviour: the seat file's frontmatter now carries
`edit: deny` / `bash: deny` / `task: deny`. A write attempt is denied by
the seat-deny overlay and by the host; the seat asks the human for every
mutating step instead of proceeding.

> "Cautious holds edit/bash/task denied, so I ask before any write and
> proceed only on an explicit approval."

## Trial 2 — balanced (daily work)

```console
$ node scripts/switch-facet.mjs set balanced
facet: balanced (permissions updated for balanced)
$ node scripts/switch-facet.mjs list
cautious
balanced (active)
long
```

Quoted behaviour: the frontmatter now carries `edit: ask` / `bash: ask` /
`task: ask`. A write proceeds after an ask; this is the default facet.

> "Balanced asks before edit, bash and task calls but otherwise works
> daily without a separate approval for reads and questions."

## Trial 3 — long (without intervention)

```console
$ node scripts/switch-facet.mjs set long
facet: long (permissions updated for long)
$ node scripts/switch-facet.mjs list
cautious
balanced
long (active)
```

Quoted behaviour: the frontmatter now carries `edit: allow` / full `bash`
with two destructive denies, plus `task: allow`. Longer runs proceed
without per-step asks, bounded by the destructive denies and the approval
interlock.

> "Long carries full edit and task permission and proceeds without
> intervention, stopping only at `rm -rf` and `git push --force`."

The three quoted results differ because the permissions differ while the
task and the thinking are the same.
