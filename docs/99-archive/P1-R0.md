## Verdicts (one per item; greppable `Verdict ([123])`)

Verdict (1) D4 plan-guard hook interception: IMPOSSIBLE — PARKED (a hook cannot intercept-and-deny a brief that contradicts the plan doc on the current version; the missing surface is a typed rejection/deny API on the session prompt-admission hook).

- Why: the only admission-time hook is `ctx.session.hook("prompt", ...)` (V2 plugins page, Hooks → Sessions → Prompt admission, fetched 2026-10-15). The live page states the denial mechanism does not exist, verbatim in substance: "Prompt hooks transform input and do not expose a typed rejection API." It further states "Session and message IDs are readonly; a hook cannot redirect admission" and "Agent mentions do not switch the session's active agent." A prompt hook can rewrite `prompt.text`, push files, and set `metadata`/`delivery` — it cannot refuse the brief.
- Why no other hook substitutes: `ctx.permission.hook("evaluate", ...)` can set `effect` to `allow`/`ask`/`deny` with `message` as the denial reason — but it fires only for permission-evaluated *actions* ("Hooks run for `allow` and `ask` decisions. An explicit configured `deny` is final and does not invoke the hook."), and prompt admission is not a permission-gated action. V2 `ctx.tool.hook("execute.before", ...)` documents only "Inspect or replace tool input before execution" — no deny/effect field is documented on the V2 tool hook (contrast the V1 `throw` precedent in `arsenal.ts`, which the V2 runtime ignores). `ctx.session.hook("context", ...)` shapes an already-admitted request (push system parts, `delete event.tools.write`, `event.options.temperature`) — it fires per model call, not at admission, and denies nothing.
- PARKED reason: D4 (plan-guard HARD) cannot be built as an admission gate on host `v2.0.27`: there is no hook that observes a brief *and* refuses it with a reason. The verdict binds `p1-planguard`: no HARD admission-denial claim may be made; only behaviors observed above exist.
- Closest achievable behaviors observed (evidence, not design): prompt-hook text rewrite / plan-file injection; permission-`evaluate` deny of downstream gated actions; `context`-hook per-request tool stripping and system-text injection.

Verdict (2) task permission-allowlist semantics: CONFIRMED (a task-level allowlist deny removes the tool from the agent description/behavior via the Task tool description mechanism).

- Observed mechanism (agents page, Task permissions section, fetched 2026-10-15): "When set to `deny`, the subagent is removed from the Task tool description entirely, so the model won't attempt to invoke it." Example shape: `agent.orchestrator.permission.task: { "*": "deny", "orchestrator-*": "allow", "code-reviewer": "ask" }`.
- Provenance details observed on the same page: rules are glob patterns evaluated in order with the last matching rule winning; agent rules merge over global config with agent precedence (permissions page, Agents section, fetched 2026-10-15). Boundary observed: "Users can always invoke any subagent directly via the `@` autocomplete menu, even if the agent's task permissions would deny it." So the deny removes the subagent from the *Task tool* description/behavior, not from the `@` menu.

Verdict (3) temperature/pinning behavior on the current version: CONFIRMED (temperature lives per agent and a per-agent model pin is honored, with the observed precedence chain).

- Where temperature lives (agents page, Temperature section, fetched 2026-10-15): per agent — `agent.<name>.temperature` in `opencode.json` (e.g. `plan: { temperature: 0.1 }`) or `temperature:` frontmatter in a Markdown agent file (e.g. `temperature: 0.1` in `review.md`). Ranges observed: 0.0–0.2 focused, 0.3–0.5 balanced, 0.6–1.0 creative; default when unset is model-specific ("typically 0 for most models, 0.55 for Qwen models"). Sibling knob `top_p` is likewise per agent.
- Per-agent pin honored (agents page, Model section, fetched 2026-10-15): `agent.<name>.model` as `provider/model-id`. Fallback chain observed: "If you don't specify a model, primary agents use the model globally configured while subagents will use the model of the primary agent that invoked the subagent." Global default is the top-level `model` key (models page, fetched 2026-10-15); global per-model options live under `provider.<id>.models.<id>.options`, and "The agent config overrides any global options here."
- Per-request override honored (V2 plugins page, Model requests, fetched 2026-10-15): `ctx.session.hook("context", (event) => { event.options.temperature = 0.2 })`. Precedence observed: "Request overrides take precedence over model defaults, which take precedence over route defaults"; `options` starts empty per call and deleting an override falls back to configured defaults. `ctx.session.switchModel` can also change the session model imperatively.
